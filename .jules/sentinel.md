## 2025-01-20 - [Fix FFI boundary vulnerabilities]
**Vulnerability:** Risk of integer overflow during text length conversions (`text.len() as i32`), buffer truncation lacking proper null termination bounds when interacting with `llama_model_desc`, and missing input validation preventing DoS via null bytes inside strings for `CString::new(s).unwrap()` across FFI boundaries.
**Learning:** Hardcoded type castings, missing error handling around `CString` constructions with untrusted input, and implicit assumptions on returned lengths from C functions can cause unpredictable behavior, application crashes, and buffer issues. `text.len() as i32` could easily overflow yielding negative lengths.
**Prevention:** Validate string length prior to casting `try_from().unwrap_or(...)`, safely handle potential `CString` panics utilizing `.ok()`, and respect C-string null termination bounds by allocating `len + 1` buffers explicitly converting output bytes using safe Rust functions like `String::from_utf8_lossy`.
